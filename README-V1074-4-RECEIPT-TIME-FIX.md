# V1.07.4.4｜修正即時行情誤判「未來時間」

## 2026-11-27 實機證據
- 09:21 V1.07.4.1：盤後候選 5 檔、REST 26 次、合格 0。
- 09:29 V1.07.4.2：5 檔中個股報價驗證不通過 3、族群方向未確認 2。
- 09:36 V1.07.4.3：REST 25 次；4 檔個股報價以「行情時間晚於檢查時間」被拒絕，4 次同業即時報價未通過；另 1 檔產業別/交易所元資料不足。
- 檢視原始碼後發現：`scan_real` 從掃描開始就固定 `now`，中間連續 25 次 REST 呼叫，後段股票的實際最後成交可能**在掃描開始之後、HTTP 回傳之前**。此前將這種正常後續成交錯判為來自未來。官方 Fugle Intraday Quote 的 `lastTrade.time` 是 microsecond UNIX timestamp，而原函式轉換方式正確，因此先修「比較時間點」而不亂改時間戳單位。

## 修正方式
- 每次收到指數 quote、同業 quote 後各自取得當時的台灣時間，再驗證報價是否為當日、非試撮、未來時間未超前、距驗證不超過 90 秒。
- 每檔個股 quote 與分鐘K取完後，在當下再驗證 quote 時間；`evaluate` 的 `now`、`verified_at`、訊號時間 `at` 均使用這個實際檢查時間。
- `clock` 可供離線單元測試注入可重現的當下時間；上線預設使用 `datetime.now(Asia/Taipei)`。
- **保留原有所有資料/策略/合規/風控門檻；不發通知、不下單、不寫 Fugle Key；不增 API 請求。**
- 若 Window 主機時間本身與資料來源不一致，仍維持 fail closed，後續須檢查 Windows 時鐘與官方 NTP，不得以任意容忍值放行。
